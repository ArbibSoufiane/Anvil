# ArbiPache 4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild ArbiPache as a portable, GUI-only C# / Avalonia app that runs Apache, PHP worker
pools and MariaDB/MySQL on Windows for development and for internet-facing production.

**Architecture:** `ArbiPache.Core` holds all logic (pure where possible). `ArbiPache.Agent.exe`
owns every running process and is the only writer of `data\`; it runs as a child of the GUI in
Development and as a Windows service (`NT SERVICE\ArbiPacheAgent`) in Production. `ArbiPache.exe`
(Avalonia, never elevated) talks to the Agent over JSON-RPC on a named pipe. `ArbiPache.Elevator.exe`
does the few admin-only jobs through UAC with a fixed verb set.

**Tech Stack:** .NET 10 (LTS), C# latest, Avalonia 11.3.x, CommunityToolkit.Mvvm,
Microsoft.Extensions.Hosting (+ WindowsServices), StreamJsonRpc, Scriban (templates), Certes (ACME),
BCrypt.Net-Next, MySqlConnector, Serilog, Microsoft.Windows.CsWin32, xUnit v3, Verify.XunitV3,
Avalonia.Headless.XUnit. Exact versions: latest stable at Task 0.1, pinned in `Directory.Packages.props`.

**Spec:** `docs/superpowers/specs/2026-10-27-arbipache4-design.md` (read it first; the mode values
table there is normative). UI mockup: https://claude.ai/artifact/Gt31veQvjjeYTFPVJZhHdt

## Global Constraints

- Windows x64 only: Windows 10 22H2+, Windows 11, Windows Server 2019/2022/2025.
- `TargetFramework` `net10.0-windows`; `<Nullable>enable</Nullable>`; `<TreatWarningsAsErrors>true</TreatWarningsAsErrors>`.
- No user-facing CLI. Agent and Elevator are internal executables, never documented as tools.
- `ArbiPache.exe` manifest `asInvoker`; `ArbiPache.Elevator.exe` manifest `requireAdministrator`.
- Portable: every path comes from `AppPaths`; no state in `%USERPROFILE%`; registry only for the optional HKCU Run key and the optional service.
- Downloads: HTTPS only, SHA-256 verified before anything is extracted or run.
- Publish: self-contained **folder** (`win-x64`), `PublishSingleFile=false`, `PublishTrimmed=false`, no compression/packers.
- Every child process: `CreateNoWindow=true`, `UseShellExecute=false`, assigned to the Agent's Job Object.
- Every Apache vhost is `<VirtualHost *:{port}>`; never an IP-specific vhost.
- Paths in Apache config: forward slashes, always double-quoted (`AppPaths.ForApache`).
- `data\conf\` is generated and fully regenerable. User-owned: `data\apache\httpd.conf`, `data\php\<v>\php.ini`, `data\<engine>\my.ini` (ArbiPache only edits its marked lines).
- Config test before every Apache (re)start; on failure the previous `data\conf\` is restored and running services are left alone.
- UI copy: plain language, tone of the mockup. No emoji.
- Version: single source `<Version>` in `Directory.Build.props` (starts at `4.0.0`); every change set bumps it (major / minor / patch) and adds a `CHANGELOG.md` entry, newest first.
- Commit messages: conventional (`feat:`, `fix:`, `test:`, `chore:`, `docs:`), no `Co-Authored-By` or AI attribution lines.
- Unit tests: `dotnet test tests/ArbiPache.Core.Tests` and `tests/ArbiPache.App.Tests`. Tests that need real Apache/PHP/DB binaries live in `tests/ArbiPache.Integration.Tests` with `[Trait("Category","Integration")]`, use ports 18080/18443/13306, and cache downloads in `%LOCALAPPDATA%\ArbiPache-test-cache`.

## Review Focus

1. **Paths with spaces or accents** (`D:\Mes Sites\café\ArbiPache`, site roots likewise): Apache must start and serve them. Pinned by `Paths_with_spaces_and_unicode_render_quoted` (Task 1.7, Task 3.4) and `Real_httpd_accepts_unicode_root` (Task 1.8).
2. **App folder copied to another drive or machine**: first start must regenerate every absolute path (generated config, the `httpd.conf` block, `PHPRC`). Pinned by `Block_repaired_when_root_moved` (Task 1.5) and `Moved_root_regenerates_everything` (Task 1.12).
3. **User breaks `httpd.conf` by hand, then changes a setting**: change refused, error shown, sites keep serving. Pinned by `Failed_test_restores_previous_conf_byte_identical` (Task 1.8) and `Apply_failure_keeps_apache_running` (Task 1.12).
4. **Laravel copy under an IP site's `/demo` folder**: `/demo/login` must reach `/demo/index.php`. Pinned by `Php_mount_gets_fallback_resource` (Task 3.4) and the Checkpoint 3 manual check.
5. **Port 80/443 held by IIS, HTTP.SYS or another app**: Start is refused with the holder's name and a fix, not a silent failure. Pinned by `HttpSys_registration_on_80_is_a_finding` (Task 1.11) and `Dashboard_shows_port_conflict_finding` (Task 1.13).
